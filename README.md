# Credit Default Scoring

Проект по кредитному скорингу: предсказание вероятности дефолта заёмщика в течение 2 лет. Датасет [Give Me Some Credit](https://www.kaggle.com/c/GiveMeSomeCredit) (Kaggle), 150 000 заёмщиков, 10 признаков + бинарная цель.

**Стек:** Python, pandas, scikit-learn, CatBoost, LightGBM, SHAP, PyCaret, SQLite, matplotlib, seaborn.
## Данные

| Признак | Описание |
|---|---|
| `SeriousDlqin2yrs` | Целевая: дефолт (просрочка 90+ дней) в течение 2 лет |
| `RevolvingUtilizationOfUnsecuredLines` | Утилизация кредиток и овердрафтов |
| `age` | Возраст заёмщика |
| `NumberOfTime30-59DaysPastDueNotWorse` | Просрочки 30–59 дней |
| `DebtRatio` | Долговая нагрузка |
| `MonthlyIncome` | Месячный доход |
| `NumberOfOpenCreditLinesAndLoans` | Количество открытых кредитных линий |
| `NumberOfTimes90DaysLate` | Просрочки 90+ дней |
| `NumberRealEstateLoansOrLines` | Ипотеки и кредиты под залог недвижимости |
| `NumberOfTime60-89DaysPastDueNotWorse` | Просрочки 60–89 дней |
| `NumberOfDependents` | Количество иждивенцев |

Доля положительного класса — **6.68%**, выраженный дисбаланс.

---

## SQL-анализ (SQLite)

Данные загружены в SQLite, выполнены три паттерна запросов:

**1. Базовый агрегат.** Средний возраст (52.3 года), default rate (6.68%), количество заёмщиков.

**2. JOIN + оконная функция.** `RANK() OVER (PARTITION BY age_band ORDER BY MonthlyIncome DESC)` — ранжирование дохода внутри возрастных групп. JOIN с таблицей `age_bands` обнаружил аномальную запись `age=0` (150 000 → 149 999 строк).

**3. GROUP BY / HAVING.** Доля дефолтов по возрастным группам:

| Возраст | Default rate |
|---|---|
| 18–29 | 11.7% |
| 30–44 | 9.5% |
| 45–59 | 7.0% |
| 60–74 | 3.4% |
| 75+ | 2.0% |

Молодые заёмщики уходят в дефолт почти в 6 раз чаще пожилых.

## Препроцессинг

- **`age=0`** — удалена как физически недостоверная (1 строка из 150 000).
- **`MonthlyIncome`** — заполнен медианой, добавлен флаг `MonthlyIncome_was_missing`.
- **`NumberOfDependents`** — заполнен 0, добавлен флаг `NumberOfDependents_missing`. Связь пропуска с таргетом проверена χ²-тестом: p-value = 8.2e-08, связь статистически значима.
- **Аномалии 96/98 в просрочках** — заменены на 0 с сохранением флагов `_missing` в каждом из трёх признаков.
- **Лог-преобразования** — для скошенных признаков: `RevolvingUtilization_log`, `DebtRatio_log`, `MonthlyIncome_log`.

**Итог:** 149 999 строк, 19 признаков, пропусков нет.

## Сравнение моделей

Первичный бенчмарк в PyCaret по 5-fold StratifiedKFold:

| Модель | ROC-AUC | PR-AUC |
|---|---|---|
| GBC | 0.8615 | — |
| LightGBM | 0.8612 | — |
| CatBoost | 0.8610 | — |
| XGBoost | 0.8495 | — |
| RF | 0.8390 | — |
| Logistic Regression | 0.8303 | — |

Три бустинговые модели показали близкие результаты, поэтому по этому бенчмарку явного преимущества одной модели не наблюдается. Финальный выбор — **CatBoost**.

Дополнительно прогнаны три модели через `cross_validate` с двумя метриками:

| Модель | ROC-AUC | PR-AUC |
|---|---|---|
| CatBoost | 0.8636 ± 0.0058 | 0.4009 ± 0.0078 |
| LightGBM | 0.8581 ± 0.0051 | 0.3902 ± 0.0092 |
| Logistic Regression | 0.8572 ± 0.0062 | 0.3573 ± 0.0092 |

Logistic Regression почти догнал бустинги по ROC-AUC, но проиграл по PR-AUC. Это подтверждает, что при дисбалансе ROC-AUC менее информативен.

## Финальный пайплайн

- **Сплит:** 70% train / 15% validation / 15% test.
- **Test не использовался** для early stopping и threshold tuning — только для финальной оценки.
- **Модель:** CatBoost, `iterations=1000`, `depth=6`, `learning_rate=0.05`, `early_stopping_rounds=50`.
- **Early stopping:** лучшая итерация — 309.
- **Threshold tuning:** на validation по F1 → порог = 0.238.

**Интерпретация:**

* **ROC-AUC = 0.8666** — модель хорошо ранжирует клиентов по уровню риска.
* **PR-AUC = 0.4101** при baseline 0.0668 — примерно в 6 раз выше доли положительного класса, что особенно важно при дисбалансе.
* **KS = 0.575 (p < 0.001)** — максимальное расстояние между распределениями model score для дефолтных и недефолтных клиентов.
* При threshold **0.238** модель обнаруживает **46.0%** фактических дефолтов с precision **43.6%**.
* **F1 = 0.448** отражает компромисс между precision и recall при выбранном пороге.
* **Brier score ≈ 0.049** используется для оценки качества вероятностных прогнозов; дополнительно калибровка проверяется через calibration curve.

Threshold **0.238** выбран на validation по максимальному F1 и не подбирался на test.

## Интерпретация модели

**Feature importance (CatBoost):**
Топ-5: `RevolvingUtilization_log`, `RevolvingUtilization`, `DelinquencySeverity` (FE), `age`, `TotalDelinquencies` (FE).

Две из пяти важнейших фичей — результат feature engineering.

**SHAP summary:**
Подтверждает feature importance и показывает направление + нелинейность:
- `RevolvingUtilization`: рост риска при значениях > 0.5, скачок после 1.0 (превышение лимита).
- `age`: двусторонняя нелинейность — и молодые, и пожилые повышают риск, средний возраст снижает.
- Просрочки: монотонно повышают риск, длинный хвост вправо.
- `DebtRatio` и `MonthlyIncome`: вклад у нуля, слабые одиночные предикторы.

**Waterfall для отдельного клиента:**
Модель объясняет решение логично: молодой клиент (30 лет), 9 просрочек (включая 5 по 90+ дней), превышенный лимит по кредиткам, 4 иждивенца — проблемный заёмщик. Все фичи тянут в сторону дефолта, ни одна не снижает риск.

## Финальные выводы

1. **PR-AUC как основная метрика.** При дисбалансе 6.68% ROC-AUC менее информативен.
2. **Трёхсторонний сплит.** Validation для threshold tuning и early stopping, test — только для финальной оценки.
3. **Threshold как бизнес-решение.** Порог 0.238 — F1-оптимум. При других приоритетах (Recall vs Precision) порог сдвигается.

## Ограничения

- **Датасет 2011 года.** Не отражает текущий кредитный рынок.
- **Нет проверки на drift.** В продакшене нужен мониторинг PSI / KS по фичам и скорам.
- **Множество признаков для бустингов избыточны (предполагалось, что будет использоваться также LR).** `DelinquencyUtilization` и `SevereLateHighUtilization` не дают прироста для CatBoost — оставлены для сравнительного эксперимента с линейными моделями.

## Возможные улучшения

- **Optuna для гиперпараметров.**

- **Подбор порога в зависимости от требований бизнеса.** Порог по F1 — базовый компромисс. В банке он подбирается через cost matrix: если FN дороже FP в 5 раз, порог сдвигается вниз, Recall растёт.

- **WOE-binning для LogReg.** LogReg дал 0.857 — почти как бустинги. С классическим скоринговым подходом (Weight of Evidence) можно догнать CatBoost и стать полностью интерпретируемым.

- **Внешние данные.** Возможно внешние данные дадут еще больше прироста
